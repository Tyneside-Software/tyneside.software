Compares each pair of corresponding bits. The result bit is 1 only if both bits are 1; otherwise it is 0.

Checking whether a bit is set:

2. Bitwise XOR (^)
Compares each pair of corresponding bits. The result bit is 1 if the bits differ; otherwise it is 0.
Truth table:

Common uses:

Toggling / flipping bits – value ^= mask flips exactly the bits that are set in the mask.
Swapping two variables without a temporary:
a ^= b; b ^= a; a ^= b;
Finding the single number that appears an odd number of times in an array (XOR of all elements).

4. Operator precedence (important when combining them)
In C-family languages (and most others):

& has higher precedence than ^
So a ^ b & c is evaluated as a ^ (b & c), not (a ^ b) & c.

Always use parentheses when mixing them if the intended order is different.
Language-specific notes

x &^ y ≡ x & ~y. There is also the assignment form &^=.
A few older BASIC dialects (e.g. FutureBasic) use ^& for NAND (~(a & b)), but this is extremely rare.

It is a binary operator that works only on integer types.
What it does
For every corresponding bit:

The result bit is 1 only if the left operand has a 1 and the right operand has a 0.
Otherwise the result bit is 0.

In other words, it clears (sets to 0) every bit in the left operand that is set in the right operand, while leaving the other bits of the left operand unchanged.
Equivalence
GoCopyx &^ y   ≡   x & (^y)
(^y is the bitwise complement / one’s complement of y.)
Truth table (single bit)






























aba &^ b000010101110
Examples
GoCopypackage main

import "fmt"

func main() {
    x := uint8(0b00001111) // 15  (binary 0000 1111)
    y := uint8(0b00000100) //  4  (binary 0000 0100)

    z := x &^ y
    fmt.Printf("%08b  (%d)\n", z, z) // 00001011  (11)
}
More examples:
GoCopy7 &^ 5   // 0b0111 &^ 0b0101 → 0b0010  (= 2)
5 &^ 7   // 0b0101 &^ 0b0111 → 0b0000  (= 0)
15 &^ 4  // 0b1111 &^ 0b0100 → 0b1011  (= 11)
Compound assignment form
There is also the combined assignment operator:
GoCopyx &^= y   // equivalent to  x = x &^ y
Example – clearing flags:
GoCopyconst (
    FlagA = 1 << iota  // 1
    FlagB              // 2
    FlagC              // 4
)

flags := FlagA | FlagB | FlagC   // 0b0111
flags &^= FlagB                  // clear FlagB → 0b0101
Why Go has a dedicated &^ operator
Go does not have a unary ~ operator (the ^ operator is overloaded: binary ^ is XOR, unary ^ is complement).
Having a dedicated &^ makes bit-clearing clean and also handles untyped constants correctly.
For example this is illegal:
GoCopyvar x uint32 = 1
x = x & ^1          // type mismatch: ^1 is treated as int
while this works:
GoCopyx = x &^ 1          // the constant 1 is properly typed in the context of &^
Precedence
&^ has the same high precedence as the other multiplication-level operators (*, /, %, <<, >>, &).
